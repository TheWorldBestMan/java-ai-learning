# 同步准备

此目录是数据库配置草案，客户端已通过本地模拟测试，但尚未连接真实 Supabase 项目验证。请勿将 secret 或 service_role 密钥放在网站或公开仓库中。

项目创建后，需要将邮箱登录模板配置为包含验证码 Token、运行并验证 setup.sql、确认 Data API 对 authenticated 角色开放、配置 RLS，并使用两个不同用户验证隔离。还需实测客户端的会话、离线同步、修订号冲突检测及草稿冲突处理。项目 URL 和 publishable key 可以公开，但必须配合正确的 RLS。请在验证前导出本地备份。

## 配置步骤

1. 在 Supabase 控制台创建或选定专用于此网站的项目；仅在你确认项目归属和费用条件后继续。
2. 在 Authentication 设置中启用邮箱登录，按官方邮件模板文档配置登录和注册邮件，使邮件显示 `{{ .Token }}` 验证码。若邮件只含链接，网站的验证码输入框不能使用该链接代替。
3. 确认目标项目和 `public` 模式没有同名的 `learning_progress` 表及策略；审阅本目录的 `setup.sql` 后，在 SQL Editor 执行，并检查表的行级安全策略及 Data API 权限。
4. 取项目 URL 和 **publishable** 公开密钥，在每台设备的网站“云同步”页面分别填写。绝不要复制 `secret` 或 `service_role` 密钥到网页。
5. 使用两个不同邮箱账号，通过客户端分别插入、读取和更新测试数据，确认一个账号不能读写另一个账号的记录；SQL Editor 管理员连接可能绕过 RLS，不能代替此项验证。验证后再导入真实进度。

本地开发需先 `npm ci`；修改客户端源码后执行 `npm run build:sync` 和 `npm test`。网站运行时使用已打包的脚本，不需要从 CDN 下载 SDK。

本 SQL 使用 create policy，重复执行前需检查已有策略；不要在已有项目盲目重复运行。创建数据库表属于外部数据变更，部署前应在目标项目核对。
